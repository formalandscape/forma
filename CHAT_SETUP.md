# Помічник FORMA

Кнопка зліва внизу відкриває помічника. Увесь чат українською незалежно від мови решти сайту. Шість запитань про послуги, територію роботи, вартість, початок співпраці, автополив і догляд за газоном розташовані по два в ряд; після відповіді можна обрати інше запитання. За замовчуванням `content.chatEndpoint: null`: це готові відповіді, а не AI. Вони працюють на GitHub Pages без сторонніх запитів. Telegram відкриває контакт власника. Чат не відкривається сам, не прокручує сторінку та не зберігає переписку в localStorage.

## Підключення справжнього AI

Підписка ChatGPT не включає оплату API. Потрібні власний проєкт OpenAI API з оплатою та Node.js-хостинг, наприклад Render Web Service. Сам ключ не надсилайте в чат і не додавайте до репозиторію чи content.js.

1. У Render створіть Web Service із цього репозиторію, runtime Node, команда запуску `npm start`, build command `npm install --omit=dev`. Оберіть тариф за потребою; безкоштовний сервер може засинати, тому перший запит може завершитися таймаутом.
2. У секретах сервісу задайте `OPENAI_API_KEY`. У змінних задайте `CHAT_ALLOWED_ORIGINS=https://mark33d.github.io`. Якщо відкриваєте сайт на самому Render, додайте його точний origin через кому (без кінцевої риски). Не використовуйте `*`.
3. За бажанням задайте `OPENAI_MODEL`; типовий — `gpt-4.1-mini`, із лімітом 500 токенів відповіді. Переконайтеся, що проєкт API має доступ до обраної моделі. Встановіть бюджет/сповіщення в OpenAI; це окрема оплата.
4. Після запуску сервера в `content.js` задайте `chatEndpoint: 'https://ВАШ-СЕРВІС.onrender.com/api/chat'`. Для сайту на тому самому Node-сервері можна використати `/api/chat`. Оновіть версію імпорту content.js у app.js та версію app.js у index.html, опублікуйте сайт.
5. Перевірте реальне запитання, українську відповідь незалежно від мови сайту, помилку мережі та мобільний екран. До цього кроку інтеграція перевірена лише з підставними відповідями API, а не з реальною моделлю.

Віджет при підключенні показує назву «AI-помічник FORMA», поле введення та повідомлення про обробку тексту OpenAI. Сервер передає останні 10 повідомлень і поточне запитання. `store: false` вимикає збереження completion для подальшого отримання; політики обробки/утримання даних самого OpenAI залишаються чинними: https://openai.com/policies/privacy-policy/. Наш код не записує тексти повідомлень у журнали чи базу даних. Налаштування логів платформи перевірте окремо.

## Межі та захист

Бот радить лише щодо саду, послуг і підготовки консультації. Він не виконує дій, не надсилає заявки, не підтверджує ціни чи бронювання. Затверджені власником відповіді й перелік послуг беруться з chat-copy.js, контакти — з content.js, системні правила — з chat-api.mjs. Текст відповіді відображається через textContent; HTML та посилання з відповіді не виконуються. Перемикання мови сайту не змінює чат чи переписку. Сервер приймає для чату лише language: uk та інструктує модель відповідати українською, стисло: до 2–3 речень або невеликий перелік.

Сервер перевіряє origin, метод, JSON, ролі, розмір запиту (64 KiB), довжину історії й таймаут. Ключ залишається лише на сервері. Базові ліміти на один процес: 3 паралельні запити, 40 на годину, 200 за добу, 10 за хвилину на адресу з'єднання. За проксі останній ліміт може бути спільним для відвідувачів. Ліміти в пам'яті скидаються при перезапуску; для кількох інстансів або значного трафіку потрібні спільне сховище лімітів та захист платформи від ботів. CORS не є автентифікацією: автоматизовані клієнти можуть підставити Origin. Обмеження витрат у провайдера та обмеження сервера потрібні разом.

Локально задайте OPENAI_API_KEY через секретне середовище та CHAT_ALLOWED_ORIGINS=http://localhost:3000, а endpoint — `/api/chat`. Не публікуйте локальну конфігурацію. `npm test` перевіряє сервер із mock API, без витрат і передачі даних OpenAI.

## Анімації чату

Готові відповіді мають візуальну імітацію набору: три крапки протягом близько 3 секунд, потім плавна поява літер за 1,4–4,4 секунди залежно від довжини. Це анімація готового тексту, а не звернення до моделі. Для підключеного AI та сама анімація запускається після отримання відповіді. Під час набору інші запитання тимчасово недоступні; «Новий діалог» скасовує поточний набір і запит. Закриття залишає переписку для наступного відкриття. Для екранних читачів відповідь оголошується цілком після завершення набору. При `prefers-reduced-motion: reduce` готова відповідь з’являється одразу, без затримки й анімацій.
